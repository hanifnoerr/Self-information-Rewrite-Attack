# SIRA, CoDA, and SPIA on Google Colab L4

This notebook compares three watermark-attack methods using 10 shared KGW
watermarked samples on a Google Colab L4 GPU.

[Open the six-model notebook in Google Colab](https://colab.research.google.com/github/hanifnoerr/Self-information-Rewrite-Attack/blob/codex/browser-colab-l4/SIRA_COLAB_L4.ipynb)

## Experiment Design

The three attack methods are:

1. **SIRA** rewrites high-self-information tokens.
2. **CoDA** changes low-information context anchors immediately before
   high-self-information tokens.
3. **SPIA** prepends `student_id: 35571241` to the untouched watermarked text.

SIRA and CoDA both run with the same six attack/rewrite models:

| Family | Small | Large |
|---|---|---|
| Llama | Llama 3.2 3B, bf16 | Llama 3 8B, 4-bit |
| Gemma 4 | Gemma 4 E2B, bf16 | Gemma 4 E4B, bf16 |
| Qwen 2.5 | Qwen 2.5 3B, bf16 | Qwen 2.5 7B, 4-bit |

The exact model names are stored in:

```text
config/model_matrix_l4.json
```

This produces:

- 6 SIRA results;
- 6 CoDA results;
- 1 SPIA result.

The final dataframe therefore contains 13 attack rows.

## Why SPIA Does Not Use an LLM

The watermark is embedded in text generated by an LLM, but an attack does not
have to call another LLM. SPIA is a model-independent post-processing attack
against the watermarked text and detector:

```text
student_id: 35571241
<original watermarked text>
```

Running SPIA once per attack model would generate six identical outputs and
would falsely imply that SPIA depends on Llama, Gemma, or Qwen. It is therefore
run once as a shared baseline.

The six configured models are **attack/rewrite models**. The shared watermarked
source text is generated with OPT-1.3B so every attack receives identical input.
Testing six different watermark-generating models would be a separate
experiment.

## Fair Comparison

Every attack receives:

- the same OPT-1.3B-generated watermarked text;
- the same random C4 subset;
- the same KGW configuration;
- the same threshold of 30 where applicable;
- the same 10-sample limit.

SIRA and CoDA are paired by model. The comparison dataframe reports:

- SIRA attack success rate;
- CoDA attack success rate;
- `coda_minus_sira_asr` for the same model;
- semantic similarity;
- average watermark score;
- CoDA anchor count and anchor rate;
- quantization and failed-model status;
- SPIA attack success rate.

The default success criterion is:

```text
attack success rate >= 0.80
semantic similarity >= 0.75
```

## CoDA

CoDA uses the same model for self-information calculation and anchor rewriting:

1. Identify high-self-information target tokens.
2. Leave each target token visible.
3. Select a low-information token immediately before the target.
4. Replace only that anchor with a natural alternative.

For KGW with `prefix_length = 1`, changing the previous token changes the
green-list context for the following token.

Example:

```text
Original: North America and Europe
CoDA:     North America as well as Europe
```

Run one CoDA model directly:

```bash
python scripts/run_coda_attack.py \
  --input_path /content/sira_outputs/watermarked/KGW_response.json \
  --output_path /content/sira_outputs/coda_models/llama_3_2_3b/coda_attack.jsonl \
  --model_name meta-llama/Llama-3.2-3B-Instruct \
  --threshold 30 \
  --dtype bf16 \
  --max_samples 10
```

Run the complete CoDA matrix:

```bash
python scripts/run_coda_matrix_l4.py \
  --config_path /content/Self-information-Rewrite-Attack/config/model_matrix_l4.json \
  --repo_dir /content/Self-information-Rewrite-Attack \
  --input_path /content/sira_outputs/watermarked/KGW_response.json \
  --output_root /content/sira_outputs \
  --samples 10
```

## SPIA

than model rewriting.

## Paper Comparison Caveats

Only the Llama 3B and 8B SIRA rows have corresponding paper ASR values. Gemma,
Qwen, CoDA, and SPIA were not reported by the paper, so their
`paper_attack_success_rate` values remain blank.

The paper used 500 C4 samples, bf16, and A100 GPUs. A 10-sample L4 experiment is
a preliminary comparison, not an exact reproduction.
